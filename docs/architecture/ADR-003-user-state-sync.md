# ADR-003：用户状态（收藏/快照/对比）同步设计

- 状态：已接受（Accepted，其中「动态化设计」为预留方案，未实施）
- 日期：2026-09-09
- 关联：ADR-001（静态站=正式产品、wan-api=staging backend、feature flag 灰度）

## 现状（当前产品行为）

静态站的收藏/筛选快照/对比列表**只存 localStorage**：

- 只保存稳定 `job_id`、条件与数据版本，不复制岗位正文（岗位正文永远实时来自静态数据层）；
- 带版本号与容量上限，损坏时按版本丢弃重建，不允许坏数据拖垮页面；
- 引用目标校验：岗位在本周期不存在/已排除时，列表项标记失效而非报错；
- CSV 导出走安全转义（防公式注入），导出内容即用户本地全部状态（对冲换机丢失）。

## 云同步预留设计（wan-api 已具备的能力）

wan-api 侧已实现并有门禁：注册（永远普通用户，管理员唯一路径=create_admin）→ 登录
→ access token（Bearer，30min）+ refresh token（JSON body、服务端 sha256 存储、单次
轮换、重用撤销 family、logout 撤销 family）→ 收藏/快照/对比 CRUD（≤4 对比数据库级
约束、引用必须是 active 岗位、excluded 拒绝）→ 限流（login 5/5min、register 5/5min、
refresh 30/min、logout 10/min；memory 原子 / Redis Lua 双后端，Redis 不可达 fail-open）。

### 未来静态站接入的完整清单（缺一不接入，见 ADR-001）

| 模块 | 设计要点 |
|---|---|
| API client | 统一封装：超时、重试（仅幂等方法自动重试，指数退避）、错误分类（网络/4xx/5xx）、request-id 透传 |
| auth store | token 内存持有 + refresh 持久化（localStorage 隔离键）；页面刷新静默续期 |
| 登出 | 本地 token 全毁 + 服务端 logout（撤销 family）；失败也要清本地（安全优先） |
| 云端收藏/快照/对比 | 首次登录做本地→云端单向合并（本地为源，去重不覆盖）；此后写操作双写（本地先、云端异步） |
| localStorage 迁移 | 旧键版本 → 新 schema 一次性迁移，迁移失败保留旧键只读降级 |
| 冲突解决 | 以 job_id 集合并集 + updated_at 新者胜；删除用墓碑（tombstone），同步窗口内不复活 |
| 离线降级 | 云不可达 = 纯本地模式继续可用，UI 显式标示「本地模式」；绝不能因云端失败阻塞本地操作 |
| 401/403/429/503 UX | 401 静默刷新一次→失败才弹登录；403 明示权限不足；429 显示等待时长；503 显示维护态并可重试 |
| 限流 UI | 429 响应携带 retry_after → 按钮倒计时，不发无效重试 |
| 账号删除 | 云端级联删除（用户行 + 级联用户态），本地同步清空；删除后 refresh family 立即失效 |
| 数据导出 | 云端状态一键导出 JSON（与本地导出同 schema），满足可携带性 |
| 隐私 | 只同步 job_id/条件/时间戳，不同步岗位正文与个人信息；隐私政策随灰度一起上线 |
| feature flag | 默认关闭；关闭时与纯静态版逐字节等价（含错误路径）；按流量百分比灰度 |

### 非目标

- 不做多设备实时推送（轮询/拉取足够）；不做社交/分享功能；不做岗位正文云端缓存
  （正文永远来自静态数据层，ADR-002 单向流）。

## 决策

1. 当前窗口与可预见未来：**维持 localStorage 单机模式**，云同步仅以本 ADR 作为实施蓝图。
2. 接入动工的前置条件（全部满足）：ADR-001 的全链路交付承诺 + wan-api CONTRACT §7
   生产证据闭环 + 本清单逐项验收测试。
3. 用户状态的服务端语义以 CONTRACT §1 为准：wan-api 数据库是用户状态的唯一写入口，
   但永远不是岗位数据真源。

## 后果

- 正面：当前产品零账号隐私面、零云端故障面；蓝图先行使未来接入不必重新设计。
- 负面：换机/清缓存丢收藏（以导出与显式文案对冲）。
