## 二、RB-01（正式一键发布链损坏）— 已修复

- **根因**：`release.py → build_and_sync()` 仍调用 `build_pages.py →
  build_single_file_html()`；规范包 `page_content=""`，必然 RuntimeError。
- **Before**：正式链内嵌单文件四步（score_lists / 审计重生成 / build_pages /
  verify_single_file postbuild），一触即崩。
- **After**：方案 A 落地——单文件 HTML 降级为遗留存档工件，仅
  `--legacy-single-file` 显式重建（不参与 validation_status、非发布门禁）；
  正式链 = 共享流水线（`release_pipeline.py`）+ 原子提升。
- **证据**：真实 `python tools/anhui_web/release.py` 全链
  `RELEASE-EXIT=0`；manifest `validation_status=verified`、
  `tag_allowed=true`。

## 三、RB-02（锁重签风险）— 已修复

- **根因**：`clean_rebuild.py` 在 `verify_sources` 之前运行
  `gen_sources_lock.py` + 审计重生成 → 发布期间可"自动重签受污染数据"。
- **Before**：regen → relock → verify（自签闭环）。
- **After**：verify_sources 最先；全链零 `gen_sources_lock` 引用（源码扫描
  测试强制）；审计只走 `--check`（内存重算 vs 已提交工件，不落盘）；
  `verify_inputs_unchanged()` 对 9 个受锁输入做构建前后字节零漂移断言。
- **证据**：clean rebuild PASS（14 项锁一致 → 9 文件零漂移 → 事实闸 →
  verifier 302/0 → audit --check 一致）。
