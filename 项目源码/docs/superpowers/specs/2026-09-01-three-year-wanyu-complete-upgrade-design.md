# 皖域择岗三年长期维护全量升级设计说明

更新日期：2026-09-01  
基线版本：v13.4  
适用范围：2024、2025、2026 三个周期；后续年度按同一数据契约接入

## 1. 目标与边界

### 1.1 产品目标

把当前“可打开的三年静态网页”升级为一个长期维护的三年岗位数据工作台：

1. 一个统一入口切换 2024、2025、2026，不再让用户在多个孤立 HTML 之间找页面。
2. 岗位、招录、成绩、专业、来源和缺口分层保存，网页只读取已构建数据，不手工改数字。
3. 用户可以从“我是什么专业”出发筛选岗位，再按城市、考试类别、岗位类型、数据状态逐层缩小结果。
4. 每一个数字都能回答“来自哪里、是什么口径、什么时候获取、是否可比”；不能证明的值留空或标记不确定。
5. 新年度只需增加周期数据和审计结果即可发布，不复制一套页面逻辑，不改旧年度事实。
6. 发布包既能在本地离线归档，也能通过 HTTP 静态托管长期维护，并支持单周期、单模块回滚。

### 1.2 不承诺的内容

- 不把尚未发布的官方逐岗表补成 0、平均值或估计值。
- 不把镜像源、聚合源、用户标注改写成“官方已核验”。
- 不把不同考试制度、不同统计分母的数字直接做趋势结论。
- 不在没有新证据时声称“全部外部数据 100% 完整”。
- 不在第一阶段引入登录、在线编辑、复杂 AI 问答或强依赖第三方服务。

- `deliverables/maintainable/index.html`：网页壳，按周期和模块读取外置 JSON。

## 3. 方案选型

### 方案 A：继续单文件 HTML

优点：分享简单、双击可用、归档方便。  
问题：每次改一项数据都要重新生成几十 MB 的 HTML；无法做到单模块回滚，浏览器首屏和内存压力会继续增大。  
结论：只保留为归档和离线回退，不作为主维护形态。

### 方案 B：立即改成数据库和动态 API

优点：复杂检索、多人编辑和权限控制空间大。  
问题：需要部署、账号、数据库备份、网络和运维；当前数据仍有公开缺口，先上数据库不会自动提高真实性。  
结论：不作为当前主线，等访问量和多人协作需求真实出现后再启用。

### 方案 C：静态数据产品化，接口预留，逐步升级

网页保持轻量壳，数据拆成可验证 JSON 模块；先建设数据契约、审计、变更日志和发布门禁，之后再把同一份审计后的 JSON 导入 API/数据库。  
结论：推荐。它保留离线交付能力，能按周期和模块回滚，同时把未来 API 的输入提前固定下来。

## 4. 推荐总体架构

```text
source_docs / source_data / 官方公告
                 ↓
        source registry + 原始快照
                 ↓
       解析器 / 标准化 / 字段字典
                 ↓
     canonical cycle bundle（源事实层）
                 ↓
     quality checks + join checks + diff
                 ↓
       review queue（人工确认边界）
                 ↓
        audited release snapshot
                 ↓
 ┌──────────────────────────────┐
 │ site-manifest.json           │
 │ audit/three-year.json        │
 │ cycles/{year}/overview.json  │
 │ cycles/{year}/jobs.json      │
 │ cycles/{year}/catalog.json   │
 │ cycles/{year}/scores.json    │
 │ cycles/{year}/changes.json   │
 │ cycles/{year}/audit.json     │
 └──────────────────────────────┘
                 ↓
       统一工作台前端 / 离线回退
```

### 4.1 数据层

- `overview.json`：周期摘要、可用指标、更新时间、城市分布摘要；不放完整岗位行。
- `jobs.json`：岗位源事实和必要的标准化字段；继续保留 `allMajors.rows` 兼容当前读取逻辑。
- `catalog.json`：专业候选、城市/考试/岗位类型选项、字段词典和展示映射；它是展示派生物，不替换岗位原文。
- `scores.json`：成绩关联、关联方式、无法唯一匹配项和成绩口径；没有可靠关联的岗位保持空值。
- `changes.json`：相邻周期新增、撤回、字段修订、不可比原因；不把代码变化自动判成同一岗位。
- `audit.json`：当前周期来源、状态、缺口、计数对账、检查结果和人工处理记录。
- `audit/three-year.json`：全局审计索引，负责三年汇总和公开边界，不复制岗位行。
- `site-manifest.json`：每个模块的路径、版本、字节数、SHA-256、行数、招录数、缺口数和未匹配数。

### 4.2 前端层

前端拆为稳定的壳和视图模块：

```text
app-shell
├─ cycle-context
├─ overview-view
├─ compare-view
├─ jobs-search-view
├─ jobs-ranking-view
├─ job-detail-view
├─ saved-view
├─ audit-view
├─ changelog-view
└─ help-view
```

视图只通过 `DataStore` 读取数据，不直接知道文件路径；`DataStore` 只通过 manifest 解析模块路径，并完成缓存、失败提示和完整性校验。

## 5. 数据真实性设计

### 5.1 每个字段的证据表达

对会影响判断的字段，统一支持以下信息：

```json
{
  "value": "示例值",
  "status": "verified",
  "source_ref": "tools/anhui_web/data/cycles/2026/all_majors_2026.json",
  "source_locator": "row:3812 / column:专业要求",
  "observed_at": "2026-08-28",
  "method": "official_page|source_bundle|derived|safe_join|manual_review",
  "note": "展示层清洗不改变源字段"
}
```

允许的状态必须来自审计枚举：

- `verified`：源 JSON、网页内嵌数据和聚合口径已经对账。
- `source_bundle`：由当前已接入的源文件或明确增量表转化而来，需标注来源包。
- `derived`：由已核验源事实计算得到，如城市岗位数；必须提供计算口径。
- `unpublished_or_unavailable`：官方尚未发布、未取得或只有汇总口径。
- `ambiguous_join`：存在多个候选，不能唯一关联，保持空值。
- `needs_review`：已有新材料但还未进入正式发布门禁。

`0` 只表示来源明确为零；`null` 表示未知、未发布或无法安全关联；空字符串只用于没有文本值的可选展示字段。前端不得用 `value || 0` 把未知变成零。

### 5.2 稳定标识

每一条岗位建立 `record_id`，计算输入为 `cycle + exam + city + code + unit + post_name` 的规范化组合，并保存原始字段。若同一代码存在多个岗位，必须加入城市、单位或岗位序号避免碰撞；若仍不能唯一，进入 `needs_review` 而不是静默覆盖。

岗位变化比较使用三层匹配：

1. `exact_code`：周期、考试类别、城市和职位代码完全匹配。
2. `composite_exact`：代码缺失时，用单位、职位名称、城市和考试类别组合匹配。
3. `semantic_candidate`：仅提供候选给人工复核，不直接生成“同一岗位”结论。

### 5.3 专业展示契约

- 岗位原始 `zy` 永远保留。
- 展示候选来自 `catalog.json`，清理纯数字、纯符号和明显编码残片。
- “专业不限”只能在源数据明确出现时展示，不能由缺失值推断。
- 一个专业的别名或目录归类必须有词典来源、版本日期和映射说明。
- 选择专业后，页面显示“命中原始专业字段”，并允许打开岗位详情查看原文。

## 6. 全量功能设计

### 6.1 顶部全局上下文

顶部固定显示：当前周期、数据快照日期、数据状态、当前筛选数量、入口导航和全局搜索。切换周期时保留用户意图，但清除不适用于新周期的筛选值，并显示“筛选已按新周期重算”。

### 6.2 总览

- 三年总量和当前周期量分离显示。
- 岗位数、招录人数、成绩安全关联、公开边界分别展示口径。
- 城市分布只显示明确可汇总的岗位行。
- 每张指标卡有“口径/来源/更新时间”入口。
- 2026 的 116 条未唯一匹配项直接进入审计中心，不隐藏在脚注。

### 6.3 岗位检索

检索字段：单位、职位名称、专业原文、职位代码、备注、城市。  
筛选字段：专业、城市、考试类别、岗位类型、招录人数范围、来源状态、成绩状态、资料完整度。  
交互：防抖搜索、结果数量、筛选 chip、清空单项、清空全部、URL 可复制、最多 120 行首屏渲染、完整结果导出。

空状态必须说明是“没有匹配”还是“该字段未发布/不可比”，并给出清除最可能冲突筛选的动作。

### 6.4 岗位榜单

榜单不是一张固定排名表，而是当前筛选结果的聚合：

- 先选专业，再选城市、考试类别和岗位类型。
- 指标可切换岗位数、招录人数、平均每岗招录人数；后者必须标记为派生指标。
- 支持单位、岗位名称、岗位代码和来源状态的二次过滤。
- 表头冻结、排序状态明显、按筛选结果实时重排。
- 排名只在当前结果集内有效，不写成全省永久结论。
- 结果支持保存为本地筛选快照，快照记录周期、筛选条件、指标和创建时间。

### 6.5 岗位详情抽屉

点击岗位打开右侧详情，不离开检索上下文。分为四层：

1. 结论层：单位、职位、城市、招录人数、考试类别、岗位代码。
2. 条件层：专业要求、学历、学位、政治面貌、基层经历、备注等源字段。
3. 证据层：来源文件、源定位、获取日期、处理方式、审计状态。
4. 对照层：相邻周期是否存在同代码或候选匹配；若不可比，明确展示原因。

字段缺失显示“源资料未提供/本周期未取得/无法唯一关联”之一，不显示空白让用户误解。

### 6.6 三年对照

- 默认只比较 manifest 和 overview 摘要，不提前加载三年完整岗位行。
- 支持按考试类别、城市、岗位类型和专业目录查看三年曲线。
- 指标分为“可直接比较”和“仅作背景”两类。
- 岗位级变化提供新增、撤回、修订、无法判断四种状态。
- 任何跨年百分比显示分母、周期和可比性标签。
- 对 2024/2025/2026 资料覆盖不一致处显示“数据覆盖差异”，不产生伪趋势。

### 6.7 收藏与筛选快照

- 收藏只保存稳定 `record_id` 和用户备注，不复制整行数据。
- 同一岗位在新版本更新后，收藏页显示字段变化。
- 筛选快照保存查询条件和版本，不保证跨版本结果数量不变。
- 支持导出 CSV/JSON；CSV 带 UTF-8 BOM，并防止公式注入。
- 所有本地存储提供清除入口和数据说明。

### 6.8 数据审计中心

分为三块：

1. 三年摘要：岗位、人数、公开边界、未唯一匹配数。
2. 证据矩阵：按周期、考试类别、数据类型展示状态、来源、更新时间和可比性。
3. 复核队列：按高/中/低风险查看未发布、源包增量、连接歧义、字段修复和已解决事件。

每条边界要有：标题、状态、严重级别、影响范围、原始证据路径、页面表现、下一步触发条件、最后复核日期。没有官方新材料时，页面只允许更新“检查时间”，不能把状态自动改成已解决。

### 6.9 更新日志与使用说明

- 更新日志记录版本、变更模块、岗位/人数差异、来源新增、缺口变化和回滚点。
- 使用说明解释岗位数与招录人数的区别、成绩关联口径、专业展示规则、跨年不可比规则和数据更新日期。
- 用一页“如何判断一个岗位”引导用户从专业筛选、详情证据和审计状态三步核验。

## 7. UI 设计系统

### 7.1 视觉方向

采用浅色、克制、偏工作台的界面：冷白内容面、浅灰上下文底、细边框、轻阴影、较大留白、单一蓝色交互主色。参考现代 AI 工作台的输入反馈和信息层级，但不复制 DeepSeek 或其他产品的品牌色、图标、文案和布局。

### 7.2 页面结构

桌面端：

```text
┌─ 侧栏 220px ─┬─ 顶部周期/搜索/状态 64px ─────────────┐
│ 总览           │ 页面标题 + 口径说明 + 当前筛选摘要     │
│ 三年对照       ├─────────────────────────────────────┤
│ 岗位检索       │ 主内容：表格 / 图表 / 审计矩阵         │
│ 岗位榜单       │                                     │
│ 收藏           │                                     │
│ 数据审计       │                                     │
│ 更新与说明     │                                     │
└────────────────┴─────────────────────────────────────┘
```

移动端：侧栏改为底部或顶部滚动导航；筛选变为可展开面板；表格保留关键列并支持横向滚动；详情抽屉改为底部 sheet；关键口径和数据状态固定在结果顶部。

### 7.3 设计规则

- 颜色表达语义：蓝色=当前交互，青色=已核验，琥珀色=部分/源包，红色=高风险缺口，灰色=未知/不可比。
- 不用大面积深色渐变和装饰性光晕抢数据注意力。
- 统计数字与单位同层显示，卡片不制造“所有数字都是 KPI”的错觉。
- 表格优先保证对齐、可扫描、冻结表头和文字截断后的完整查看。
- 动效只用于筛选过渡、抽屉出现和加载状态，支持 `prefers-reduced-motion`。
- 输入、选择器、表格、抽屉、状态标签均有键盘焦点和可读标签。

## 8. 数据更新与运营流程

### 8.1 一次完整更新

1. 建立来源登记：公告 URL/文件、发布机构、获取时间、文件 SHA-256、周期和资料类型。
2. 保存原始快照：原文件只新增不覆盖，文件名包含周期、来源和快照日期。
3. 运行解析器：输出标准字段和原始行定位，解析失败记录错误，不丢行继续发布。
4. 运行规范化：只产生展示字段和检索索引，不能覆盖源事实。
5. 运行质量检查：计数、空值、重复键、岗位代码、招录合计、字段类型和范围。
6. 运行成绩关联：优先唯一键；多候选项进入复核队列，保持空值。
7. 运行跨周期差异：生成新增、撤回、修订候选，并对比旧 manifest。
8. 人工复核高风险事件：逐条填写证据路径和处理结论。
9. 构建模块和审计索引：生成 manifest、SHA-256 和更新日志。
10. 执行全套门禁：Python、Node、浏览器、磁盘、ZIP 五类校验。
11. 发布维护站和离线包；保留上一版目录用于快速回滚。
12. 更新交接文档：版本、命令、实际统计、公开边界和已知问题。

### 8.2 复核优先级

- P0：计数不一致、重复稳定 ID、源文件解析丢行、错误把未知写成 0、成绩错误关联。
- P1：官方新公告、单位名称缺失、跨年匹配歧义、岗位代码冲突、来源状态错误。
- P2：专业目录别名、展示排序、字段备注、低影响文本清理。

### 8.3 回滚

回滚单位为一个周期的一个模块。先恢复 `jobs.json`、`catalog.json`、`scores.json`、`audit.json` 或 `changes.json`，再恢复与之配套的 manifest；若维护站壳有问题，整个站点回退到上一版。单文件快照永远作为独立回退入口。

## 9. 性能与可靠性

- 首屏只加载 manifest、当前周期 overview 和当前视图所需模块。
- 岗位搜索使用 catalog/index 预计算选项；完整 rows 只加载一次并缓存。
- 结果渲染采用分页或窗口化，避免一次性插入上万 DOM 行。
- 模块加载设置超时、重试一次、失败后显示具体文件和版本，不显示“暂无数据”掩盖错误。
- 使用 manifest SHA-256 作为缓存失效依据；发布目录使用版本路径或原子替换。
- `file://` 只支持单文件离线快照；维护站明确要求 HTTP，页面给出本地服务命令。
- 任何外部资源必须经过审计；正式离线包默认零远程脚本、样式和字体。

## 10. 验收标准

### 数据

- 三年岗位数、招录人数、审计边界和未唯一匹配数与构建源逐项一致。
- 2026 年 116 条无法唯一匹配项继续为空并可定位到审计事件。
- 未发布、未回收和不可比值不被渲染为零或已核验。
- 专业候选不出现纯数字/纯符号编码残片；岗位详情仍能查看原始专业文本。
- 每个公开指标可展开来源、时间和方法；源包、派生、未知三类状态不混淆。

### 功能

- 一个入口可切换三年；切换后总览、榜单、检索、审计数据不串周期。
- 岗位榜单支持专业、城市、考试类别、岗位类型组合筛选，结果交集正确。
- 岗位详情能打开源字段和证据链，空值有原因。
- 筛选条件可复制、保存、清除；收藏只存稳定 ID。
- 三年对照对可比和不可比指标做清晰区分。
- 审计中心能看到三年汇总、当前周期边界、复核队列和来源路径。

### 视觉与体验

- 1440、768、390 宽度无横向页面溢出；关键表格允许局部横向滚动。
- 主色浅、层级清楚，深色仅用于文字和语义状态，不回退到深色大面积背景。
- 键盘可完成周期切换、筛选、打开详情、关闭详情和清空筛选。
- reduced-motion 下无强制位移动效。

### 发布

- 构建器、磁盘校验器和 package verifier 全部通过。
- Python 单元测试、Node 核心测试、浏览器烟测全部通过。
- ZIP 解包后的 manifest 哈希与工作目录一致。
- 每次发布都有 changelog、审计报告和可回滚目录。

## 11. 分阶段范围

### 阶段 0：基线冻结

冻结 v13.4 的 counts、hashes、公开边界和浏览器基线，建立升级前对照表。此阶段不改变数据。

### 阶段 1：数据契约与来源治理

增加 source registry、字段证据对象、专业 catalog、稳定 ID 规则、复核队列格式和差异报告。先让数据可以被长期维护，再扩大页面功能。

### 阶段 2：工作台 UI 重构

统一导航、浅色设计令牌、周期上下文、加载/失败/空状态、响应式布局和可访问性骨架。保持旧 hash 兼容，避免用户收藏的链接全部失效。

### 阶段 3：岗位决策链

把“专业 → 组合筛选 → 榜单 → 岗位详情 → 来源证据”串成一条完整路径，加入更多真实字段过滤和筛选快照。

### 阶段 4：三年比较与变化

实现可比指标、岗位变化候选、收藏变化提示和更新日志；所有不可比项明确标注，不为了图表完整而补造趋势。

### 阶段 5：审计与运营

把审计中心从展示页升级为可筛选的复核工作台，加入差异报告、发布前检查摘要、模块回滚信息和更新操作手册。

### 阶段 6：性能、质量与正式发布

完成窗口化渲染、缓存、失败恢复、无障碍、全尺寸浏览器验收和 v14.0 交付包；同步保留 v13.4 回退包。
