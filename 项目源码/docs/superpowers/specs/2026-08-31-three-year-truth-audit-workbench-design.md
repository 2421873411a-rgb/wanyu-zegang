# 三年数据真实性审计与统一工作台设计规格

## 目标

将现有 2024、2025、2026 安徽公考离线数据产品整理为一套可追溯的三年工作台：逐层核对原始资料、标准化数据和网页内嵌数据；公开所有已知缺口与证据等级；在不改变源事实、不补造未知值的前提下，统一三年页面的信息架构、视觉语言和交互入口。

## 现状与边界

- 2026 主站当前页面岗位 8,511 条、招录人数 12,006 人；分为省考 3,784、事业编 4,176、国考 551。
- 2025 周期包为 10,150 岗 / 14,721 人；2024 周期包为 10,017 岗 / 15,331 人。
- 当前已有三年独立周期页和离线构建链路，但三年对照入口不足，真实性/完整性主要散落在 manifest、核验报告和周期 gaps 中。
- “真实”只表示当前值有可定位的源证据或经过明确的安全转换；“没有缺失”不以猜测填空实现。官方尚未发布、源包未取得、无法唯一匹配的字段必须显示其状态并保留空值。
- 本轮不改变岗位事实、招录人数、成绩数值、资格结论或源文件；不联网抓取后直接写入生产数据，不把搜索结果当作已核验事实。

## 方案选择

采用“审计报告 + 三年总览视图 + 周期页统一状态条”的组合方案。

1. **只做审计报告**：风险最低，但用户仍需在多个页面间手工理解三年变化，不能满足整理和网页优化的目标。
2. **只做三年趋势页**：视觉效果直接，但没有逐字段证据链，容易把缺失掩盖在图表中。
3. **组合方案（采用）**：用脚本生成可复跑的完整性/真实性审计报告，网页新增三年对照视图并在周期页展示证据状态；数据层、展示层和缺口说明相互独立，既能交付使用，也能继续追踪后续官方公告。

## 信息架构与视觉设计

### 1. 主站新增“三年对照”视图

在 2026 主站导航中加入 `三年对照`，页面包含：

- 顶部结论条：2024 / 2025 / 2026 三个周期的岗位数、招录人数、数据状态和快照日期。
- 趋势卡：岗位数、招录人数按年度并列显示；增长率只使用岗位库已核验的总数计算，并注明“周期总量，不代表同口径官方计划变化”。
- 考试结构对照：省考、事业编、国考分别展示岗位数/招录人数；缺少某项明细时展示“未取得”，不显示为 0。
- 数据可信度矩阵：每个周期分为“源包内核对”“官方证据覆盖”“未发布/未取得”“安全未匹配”四类，显示数量和说明。
- 缺口与来源抽屉：按周期列出 `cycle.json`、主岗位 JSON、成绩清单、来源说明和 open item，链接使用离线相对路径或页面内锚点。
- 明确的操作入口：进入 2024/2025/2026 周期页、岗位检索、收藏/对比；不新增外部依赖。

视觉上沿用现有主站深蓝、暖白和橙色强调色，但将三年对照做成“档案索引”风格：年度作为横向时间轴，审计状态使用低饱和蓝/琥珀/红色标签，避免用鲜艳颜色暗示数据更可靠。卡片和表格在 390×844 下改为纵向堆叠，桌面端保持统一内容宽度和导航不换行。

### 2. 周期页统一状态条

2024、2025 周期页和 2026 主站顶部增加统一的周期/证据提示：周期状态、快照/生成日期、岗位库规模、成绩覆盖边界，以及“查看三年对照”入口。现有岗位检索、地图、收藏和对比功能不移除。

### 3. 真实性文案规则

- `已核对`：源文件/标准 JSON/页面数据三层一致，且有源路径或官方原文索引。
- `源包已收录`：值来自交付包源文件，但外部官方逐项原文没有在本包中留档。
- `未发布/未取得`：资料明确说明官方暂未发布，或本轮没有取得可复核材料。
- `无法唯一匹配`：存在多个候选岗位而成绩附件缺少城市等必要键，宁可留空。
- 禁止使用“完整无缺”“全部官方确认”等无法由审计证据支持的绝对措辞。

## 数据审计设计

新增 `tools/anhui_web/audit_three_years.py`，只读三年数据并生成 `docs/三年数据真实性与完整性审计_v11.md`。脚本不重写任何数据文件，退出码非零表示结构或三层对账失败。

### 审计对象与粒度

| 层级 | 输入 | 关键检查 |
|---|---|---|
| 源/标准数据 | `tools/anhui_web/data/all_majors_2026.json`、`data/cycles/2025`、`data/cycles/2024`、成绩清单、`source_data/` | 文件存在、周期一致、岗位键/考试类别/城市/招录人数、重复键、必填字段和允许空值 |
| 页面内嵌数据 | `deliverables/皖域择岗总览.html`、`deliverables/2025/皖域择岗总览.html`、`deliverables/2024/皖域择岗总览.html` | `PAGE_DATA`/`allMajors` 与标准 JSON 行数、总人数、考试分组、周期元数据一致 |
| 证据链 | `manifest.json`、各 `cycle.json`、源资料索引、现有核验报告 | 来源路径、生成时间、快照时间、open item、gap 和审计链可定位 |

### 必须输出的检查

1. 每周期岗位总数、招录人数、考试分类、城市分类、年度快照/生成时间。
2. 岗位主键候选重复率；`exam + city + code + recruits` 复合键重复和空值数量。
3. 关键字段空值率：考试类别、城市、职位代码、单位/职位、招录人数；允许空的成绩字段单列，不与主岗位缺失混淆。
4. 成绩字段覆盖率及安全 join 数量；把 2026 年 116 个无城市证据的重复代码列为“无法唯一匹配”，不强行绑定。
5. 源 JSON → 页面 rows 的集合/计数/金额（招录人数）对账；周期 JSON → 周期页面的对账。
6. 缺口分类：已核对、源包已收录、未发布/未取得、无法唯一匹配，并逐项列出证据文件或理由。
7. 输出可机器读取的摘要 JSON，供三年对照页面直接使用；摘要只包含统计和状态，不复制整套岗位数据。

## 实现边界与接口

- `build_pages.py`：加载三年摘要并向主站注入 `threeYearAudit`；历史周期页只注入自身状态和主站对照入口。
- `master.js`：新增 `cycle_compare` 视图渲染函数，读取 `PAGE_DATA.threeYearAudit`，不重新计算原始岗位事实。
- `master.css` / 共享 CSS：新增趋势卡、证据矩阵、缺口列表和移动端布局样式，保持无远程 CSS/font/script。
- `build.ps1` / `release.py`：构建前运行三年审计，审计失败则停止发布；成功后重建主站和两个周期页。
- `tests/test_anhui_web.py`：增加摘要结构、跨层对账和状态枚举测试。
- `tests/browser_smoke_v11.js`：增加三年对照桌面/移动视图、周期跳转、缺口面板和 file:// 离线加载检查。

## 错误处理与安全规则

- 文件缺失、周期字段不一致、主岗位行数漂移、招录人数漂移、非法状态枚举：审计失败并阻止发布。
- 官方暂未发布或未取得：审计通过但记录为缺口，页面保留“未发布/未取得”。
- 成绩 join 候选不唯一：审计通过并记录 `unresolved`，页面不填入成绩。
- 生成页面不改变源 JSON；所有修复必须通过现有“只补不盖”、白名单和审计链规则。
- 任何外部网页核验仅作为来源证据登记，必须保留 URL、访问日期和原文定位；无法复核则不改变数据状态。

## 验收标准

- 三年审计脚本可在项目根目录一条命令运行，输出报告、摘要 JSON 和非零失败码规则清楚。
- 2024/2025/2026 三周期主岗位数量与招录人数分别与现有周期包一致：10,017/15,331、10,150/14,721、8,511/12,006。
- 所有已知缺口均可在审计报告和网页状态矩阵定位，且没有被转化为 0 或伪造值。
- 三年对照视图可通过主导航进入，年度卡可跳转到对应周期页，移动端无页面级横向溢出。
- 既有 Python/Node/browser 回归保持通过，并新增三年对照视图截图；file:// 下控制台和页面错误为零。
- 交接文档、数据字典、manifest、审计报告和桌面交接包同步到同一版本号。

## 自审结论

- 未使用 TBD、TODO 或未定义接口。
- “全面/真实”被拆为可审计的覆盖、来源和安全匹配状态，没有把外部官方不可得误写成已确认。
- 审计、展示、构建和验收分别落在独立文件，页面只消费摘要 JSON，不改变岗位主数据。
- 2026 主站新增视图、历史周期状态条和报告三者共享同一摘要，避免三套口径漂移。
