# 皖域择岗三年单文件工作台设计规格

**日期：** 2026-08-31  
**目标版本：** v12.0  
**交付形态：** 一个可离线打开的主 HTML 文件，站内切换 2024、2025、2026 三个招录周期  
**状态：** 设计基线，供后续实施与验收使用

## 1. 目标与交付边界

本次升级不是把三个现有 HTML 用 iframe 或链接列表拼在一起，而是把三个周期的数据装入同一套页面结构、同一套交互组件和同一套状态管理中。正式入口固定为：

`deliverables/皖域择岗总览.html`

用户打开这一个文件后，应能完成：

1. 在 2024、2025、2026 三个周期之间切换；
2. 查看各周期的总览、地图、岗位库、岗位检索、分数模拟和证据档案；
3. 在当前视图内切换年份，而不是跳转到另一个 HTML；
4. 收藏、对比和备注跨年保留，但所有岗位都明确标注周期；
5. 在离线 `file://` 环境中使用，不依赖网络、CDN、远程字体或远程接口；
6. 清楚区分“数据已核验”“来源暂缺”“字段为空”“存在歧义”，不把缺失值写成 0，也不把推断写成事实。

现有 2024、2025 独立网页，以及“安徽十六市2026软件工程可报岗位.html”“安徽全省16市本科普通岗全包分析.html”两个兼容页，只作为 v11 可恢复备份保留，不再作为 v12 正式入口。验收完成前不得删除；验收完成后移入 `deliverables/legacy_v11/`，并从正式交付清单中降级为历史兼容文件。

## 3. 真实性与完整性表述规则

“真实、全面、没有缺失”必须拆成可验证的不同层级，网页和交付报告统一使用下列口径：

- **结构完整：** 三个周期的规定字段、考试类别、城市维度和记录主键均通过结构检查。
- **总量一致：** 页面数据、周期 JSON、审计基线和页面渲染值逐层一致。
- **来源可追溯：** 有来源文件或证据条目的数据展示来源类型、来源状态和审计时间。
- **事实不补造：** 来源没有提供的值保持为空，并显示“来源未提供”或“待核验”。
- **歧义不强连：** 2026 年 116 条成绩歧义关联继续安全留空，不用相似匹配自动填入。
- **已知缺口可见：** 2024、2025 周期登记项，以及东至县 30 岗成绩公告未发布、部分省直直接证据不可得、`0801048` 用户标记、3 条国考备注等问题进入已知缺口清单。

当前审计快照中的逐周期缺口如下，v12 必须逐条继承并重新核验：

- 2024：省考合格/缴费官方无逐岗表；拟聘用市级批次约 30+ 批未回收；133 个定向岗主表行由镜像/分数线源合成且已标注；事业编下半年官方原始 XLSX 未逐单位回收；候选复合键存在 1 个重复键、涉及 2 行，必须按原始记录保留并单列检查。
- 2025：省考合格/缴费官方无逐岗表；事业编逐岗报名人数官方未发布，仅有考区汇总；事业编上半年单位名称列待修复；拟聘用材料覆盖 13 市和省直，仍缺 4 市。
- 2026：事业编页面比当前组件源包增加 54 岗/55 人且已有构建来源说明；东至县下半年 30 岗成绩公告未发布，省直除粮食局 8 岗外的 564 岗实证不可得；`0801048` 待官方复核；`300110013003`、`300147355001`、`300147357001` 三条国考备注待官方复核；116 个成绩附件项无法唯一匹配。

因此，v12 可以声明“结构与总量通过复核”，但在外部官方证据尚未补齐时，不得声明“三年全部字段均已获得官方原文证明”。

## 4. 信息架构

### 4.1 顶层导航

正式主导航按用户任务排序：

1. 三年总览
2. 岗位地图
3. 全岗位库
4. 岗位检索
5. 分数模拟
6. 机会洞察
7. 待遇基准（2026 快照）
8. 收藏 / 对比
9. 证据档案

其中“三年总览”允许并排比较三个周期；其余岗位视图默认只读取当前激活周期。待遇数据不随周期选择器伪装成历史数据，标题必须始终标明“2026 快照”。

### 4.2 周期切换

页面顶部设置常驻分段控制器：`2024｜2025｜2026`。切换规则如下：

- 在支持三年的视图中保留当前视图，只替换激活数据集并重绘；
- 清空不适用于新周期的筛选项，并给出一次性轻提示；
- 关闭当前岗位详情抽屉，避免旧详情和新列表同时出现；
- 收藏、对比、备注继续保留，但每条记录都带周期标签；
- URL 同步为 `?cycle=2025&metric=jobs#jobs_search`，刷新后能恢复周期和视图；
- 浏览器前进、后退必须可恢复切换历史；
- 不允许把一个周期的筛选统计、成绩数据或岗位详情混入另一个周期。

### 4.3 页面上下文栏

主导航下设置周期上下文栏，始终显示：

- 当前周期；
- 当前周期岗位数和招录人数；
- 当前视图的数据范围；
- 审计状态与最后构建时间；
- 已知缺口数量和“查看详情”入口。

## 5. 视觉设计系统

### 5.1 视觉方向

采用“公共信息档案馆 + 决策工作台”的视觉语言，避免常见 AI 渐变、大量发光卡片和装饰性空洞文案。

- 背景：暖白和浅纸色，保持长时间阅读舒适；
- 主色：深蓝，代表正式信息与结构；
- 辅色：克制的青绿色，代表可交互和已核验；
- 状态色：琥珀表示来源暂缺，暗红表示歧义或待处理；
- 图表：优先使用纹理、标签和线型区分，颜色不作为唯一编码；
- 字体：仅使用系统字体栈，保证离线和 Windows 环境一致；
- 阴影：只用于层级和浮层，不用大面积霓虹或玻璃拟态。

### 5.2 布局与响应式

- 桌面端：12 栏网格，最大内容宽度控制在可读范围；
- 平板端：8 栏网格，筛选器可折叠；
- 手机端：4 栏网格，表格改为摘要卡片或横向可控滚动；
- 断点重点检查：1180px、840px、720px；
- 周期选择器在窄屏保持可见，不被折叠菜单隐藏；
- 详情抽屉在手机端切换为全屏层，保留明确关闭按钮和焦点返回。

### 5.3 无障碍与打印

- 周期选择器使用 `role="tablist"`、`role="tab"` 和 `aria-selected`；
- 所有交互元素支持键盘操作和明显的 `:focus-visible`；
- 周期切换和结果数量变化通过 `aria-live="polite"` 播报；
- 状态不能只靠颜色表达，必须配图标或文本；
- 尊重 `prefers-reduced-motion`；
- 打印样式隐藏操作控件，保留标题、周期、筛选条件、数据来源和页码信息。

## 6. 单文件数据架构

### 6.1 构建期模型

新增 `tools/anhui_web/unified_cycle_bundle.py`，提供纯函数式装载边界：

```python
@dataclass(frozen=True)
class CycleBundle:
    cycle: str
    label: str
    all_majors: dict[str, object]
    jobs: dict[str, object]
    records: list[dict[str, object]]
    score_lists: dict[str, object]
    cycle_info: dict[str, object]
    audit: dict[str, object]

def load_cycle_bundle(root: Path, cycle: str) -> CycleBundle: ...

def build_unified_bundles(
    root: Path,
    cycles: tuple[str, ...] = ("2024", "2025", "2026"),
) -> dict[str, CycleBundle]: ...

def global_record_id(cycle: str, record_id: str) -> str:
    return f"{cycle}:{record_id}"
```

这层必须消除现有 `_apply_cycle_paths(cycle)` 对全局路径的依赖，保证同一进程可以无串扰地装载三个周期。

### 6.2 HTML 嵌入

主 HTML 内只保留一份 HTML 结构、CSS 和 JavaScript。三个周期的数据分别写入独立 JSON 载荷：

```html
<script type="application/json" data-cycle-payload="2024">...</script>
<script type="application/json" data-cycle-payload="2025">...</script>
<script type="application/json" data-cycle-payload="2026">...</script>
```

首次启动只解析默认周期和三年总览所需的轻量审计摘要。2024、2025 大载荷在用户首次切换时解析并缓存，避免启动阶段同时 `JSON.parse` 全部约 67 MiB 数据。

构建器必须把 `<`、`>`、`&` 和可能结束 `script` 的序列安全转义，防止数据文本破坏页面结构。

### 6.3 浏览器运行时

新增 `tools/anhui_web/templates/cycle-runtime.js`，导出唯一周期状态源：

```javascript
window.WanyuCycleStore = {
  listCycles(),
  getCycle(),
  getBundle(cycle),
  activate(cycle, { source = "ui", preserveView = true } = {}),
  subscribe(listener),
  toGlobalId(cycle, recordId),
};
```

周期变化时触发 `wanyu:cyclechange`，事件详情为：

```javascript
{ cycle, previous, bundle, source, preserveView }
```

现有 `master.js`、`product-all.js`、`product-jobs-search.js`、`product-score-sim.js` 等脚本不得再在启动时永久捕获 `window.productData`。它们必须通过状态源读取当前 bundle，并提供幂等重绘函数。

## 7. 功能迭代规则

### 7.1 三年总览

- 固定展示三年岗位数、招录人数和三类考试拆分；
- 支持按岗位数、招录人数切换指标；
- 展示同比绝对变化和百分比变化，但基数为 0 时不计算百分比；
- 每个数字可追溯到审计摘要；
- 三年总览不受当前周期筛选条件污染。

### 7.2 岗位地图与全岗位库

- 地图、城市榜单、岗位表格只读取当前周期；
- 切换周期后地图分级、榜单、总数和筛选项同步更新；
- 对当年不存在的城市/类别组合显示“无记录”，不显示为缺失异常；
- 表格继续分页或虚拟化，禁止一次渲染全量约 28,678 条记录。

### 7.3 岗位检索与详情

- 关键词、城市、考试类别、专业、学历等筛选器按当前周期重建选项；
- 切年时清除非法筛选值，保留仍合法的通用值；
- 详情页固定展示周期、全局记录 ID、来源状态和字段缺失说明；
- 分享链接包含周期和记录 ID，刷新后能定位同一岗位；
- 任何成绩歧义关联以“未自动关联”展示。

### 7.4 分数模拟

- 只使用当前周期的成绩列表和可用关联；
- 116 条 2026 歧义关联不进入模拟样本；
- 无成绩数据时展示样本不足，不生成伪精确概率；
- 模型权重、输入区间和样本量在结果旁可见；
- 切换周期后重新计算，不沿用上一周期结果。

### 7.5 收藏、对比、备注

新版本键名使用 `v2`：

- `wanyu.jobSaved.v2`
- `wanyu.jobCompare.v2`
- `wanyu.jobNotes.v2`
- `wanyu.jobGroups.v2`

记录主键统一为 `周期:原记录ID`，例如 `2025:340101001`。首次运行把旧 `v1` 记录安全迁移为 `2026:<id>`，保留原值并写入迁移标记；迁移失败时不删除旧键。

跨年对比允许并排查看字段，但不得把不同周期岗位直接汇总成同一当年统计值。卡片和导出内容必须显示周期。

### 7.6 待遇基准与证据档案

- 待遇数据固定标注“2026 快照”，不随周期选择器改变年份标签；
- 2026 有 Word 来源归档时展示对应档案入口；
- 2024、2025 只有 JSON、证据表和缺口清单时，明确写明档案层级不同；
- 证据档案支持按周期、来源状态和缺口类型筛选；
- 所有审计时间使用构建时间，不伪装成来源发布日期。

## 8. 反复核验方案

数据要经过以下八层闭环，每层都有机器输出和失败条件：

1. **文件盘点层：** 检查规定路径、文件大小、SHA-256 和意外重复文件；
2. **结构层：** 检查 JSON 可解析、必需键、字段类型、记录主键和周期值；
3. **总量层：** 对照冻结基线检查周期、考试类别、城市的岗位数和招录人数；
4. **关联层：** 检查重复主键、成绩关联、未消歧数量和已知例外；
5. **构建对象层：** 检查 `CycleBundle` 与源 JSON 的计数和抽样记录完全一致；
6. **HTML 嵌入层：** 从最终 HTML 反解析三个载荷，重新计算哈希和总量；
7. **浏览器渲染层：** 逐周期切换，核对 DOM 总数、筛选结果、详情和 URL 状态；
8. **压缩包层：** 从最终 ZIP 解压到临时目录，再运行一次入口、哈希和浏览器冒烟检查。

执行时机固定为：构建前、构建后、打包后。已知缺口只有在缺口 ID、数量和说明完全匹配时才允许通过；新增缺口或旧缺口数量漂移必须失败。

机器报告输出：

- `tools/anhui_web/data/single_file_verification_v12.json`
- `tools/anhui_web/data/single_file_diff_v12.json`

人读报告输出：

- `docs/三年单文件数据复核报告_v12.md`

## 9. 性能预算

现有三个主页面合计约 67.1 MiB。v12 只复用一份界面资源，预算如下：

- 目标 HTML 体积不超过 75 MiB；
- 硬性上限 80 MiB，超过即构建失败；
- 当前验收机器首次 `file://` 可交互时间目标不超过 8 秒，硬性不超过 12 秒；
- 首次切换到未解析周期目标不超过 1 秒，硬性不超过 2 秒；
- 数据已激活后，常用筛选响应目标不超过 150ms，硬性不超过 300ms；
- 列表 DOM 常驻行数设置上限，禁止把三年全量记录同时渲染。

性能报告记录机器环境、浏览器版本、文件大小、三次测量中位数和最慢值，避免只报告一次最好结果。

## 10. 发布与回滚

### 10.1 正式交付目录

正式交付根目录只突出：

- `皖域择岗总览.html`
- `HANDOFF.md`
- `MANIFEST.txt`
- 数据字典、真实性复核报告和必要说明文件

2024、2025 旧页面及两个 2026 兼容页进入 `legacy_v11/`，不再让用户在多个网页之间判断入口。

### 10.2 回滚条件

满足以下任一条件立即停止 v12 替换并保留 v11：

- 任一冻结总量不一致；
- 周期切换出现跨年数据串扰；
- 旧收藏迁移造成数据丢失；
- 最终 ZIP 不能在新的临时目录离线打开；
- 文件超过 80 MiB 或首次可交互超过 12 秒；
- 已知缺口被隐藏、改写成 0 或被误称为已核验。

回滚只替换正式入口文件，不删除 v12 构建产物和失败报告，以便定位问题。

## 11. 完成定义

只有同时满足以下条件才可宣布交付：

- 一个主 HTML 内可切换三个周期，核心视图均能重绘；
- 三个周期冻结总量和考试类别分项全部一致；
- 页面、机器报告、人读报告对已知缺口表述一致；
- Python 单元测试、Node 数据测试、浏览器冒烟、无障碍关键路径和 ZIP 解包复测全部通过；
- v1 收藏/对比数据迁移与回退路径通过浏览器验证；
- 正式交付根目录不再要求用户打开多个 HTML；
- `HANDOFF.md` 明确唯一入口、数据口径、已知限制和复核命令；
- 最终文件和压缩包生成 SHA-256，且复核报告记录该哈希。
