# 皖域择岗长期维护网站架构方案 v2

版本：v14.0  ·  日期：2026-09-01  ·  范围：2024、2025、2026 三个周期

## 1. 交付结论

维护站采用“统一网页壳 + 外置 JSON 数据模块”的长期形态。用户只进入一个 `index.html`，在页面内切换周期、总览、三年对照、岗位榜单、岗位检索、收藏快照和数据审计；岗位原文不再嵌在维护站 HTML 中。

单文件 `deliverables/皖域择岗总览.html` 继续保留为可双击打开的离线归档与回退入口。它是归档快照，不承担日常单模块更新；日常更新优先替换维护站对应 JSON，再跑门禁。

## 2. 模块边界

```text
官方公告 / 已归档源文件
          ↓
周期 bundle + 来源登记 + 质量审计
          ↓
┌────────────────────────────────────────────┐
│ data/site-manifest.json                    │ 入口、版本、哈希
│ data/cycles/<cycle>/overview.json          │ 摘要
│ data/cycles/<cycle>/jobs.json              │ 岗位源事实与完整岗位行
│ data/cycles/<cycle>/catalog.json           │ 专业/城市/考试/类型目录
│ data/cycles/<cycle>/positions.json         │ 检索索引、稳定 ID、证据引用
│ data/cycles/<cycle>/scores.json            │ 成绩索引、关联边界、待复核项
│ data/cycles/<cycle>/changes.json           │ 相邻周期变化与可比性
│ data/cycles/<cycle>/audit.json             │ 周期来源、缺口、质量状态
│ data/audit/three-year.json                 │ 三年汇总
│ data/audit/review-queue.json               │ 去重后的复核队列
│ data/map/anhui.json                        │ 真实十六市地图几何（无岗位数）
└────────────────────────────────────────────┘
          ↓
DataStore → 视图 → 详情抽屉 / 收藏 / 导出
```

模块职责固定如下：

| 模块 | 放什么 | 不放什么 |
| --- | --- | --- |
| `overview` | 周期摘要、城市汇总、证据摘要 | 完整岗位行 |
| `jobs` | 所有岗位原始字段、岗位行、岗位级状态 | 展示层专业别名 |
| `catalog` | 可读专业候选、城市/考试/类型选项、计数 | 代替原始专业字段 |
| `positions` | 稳定 `record_id`、检索字段、详情证据引用 | 重新改写源事实 |
| `scores` | `bs`、`ms`、`by_key`、`keyed.unresolved` 全部成绩索引 | 把待复核成绩绑定到猜测岗位 |
| `changes` | exact/composite/待复核匹配与变化状态 | 把语义候选直接称为同一岗位 |
| `audit` | 周期证据、来源、缺口、统计对账 | 完整岗位行 |
| `review-queue` | 公开边界和复核事件的可操作队列 | 隐藏或抹平缺口 |
| `map` | 从 `anhui_340000_full.json` 投影的十六市路径、城市标签坐标 | 岗位计数、推断边界、伪造的“省直市” |

## 3. 数据真实性规则

允许状态只有：`verified`、`source_bundle`、`derived`、`unpublished_or_unavailable`、`ambiguous_join`、`needs_review`。`null` 表示未知、未发布或无法安全关联；来源明确为零时才使用 `0`。

每个影响判断的值都应能够回到：来源文件、源定位、获取日期、处理方式和说明。镜像、聚合、源包增量和用户标记不得在页面中伪装成官方逐岗结论。

专业目录是派生展示层：纯数字、纯符号和编码残片不作为可选专业；岗位原始 `zy` 永远保留，用户打开详情可以核对原文。

成绩关联使用 `exam|city|code|recruits` 复合键。没有城市且存在多个候选时进入 `ambiguous_join`，不把成绩写进任意岗位。竞争分母按报名、考试人数和国考进面名单分开，分母不同不做同比或排名。

## 4. 前端与交互

- 顶部只承担品牌、当前周期、入口导航和加载状态，采用冷白/雾蓝工作台，不使用大面积深色装饰。
- 岗位榜单先选专业，再选城市、考试、岗位类型；候选来自本周期原始岗位行，不能出现纯数字专业。
- 岗位检索按 120 行分页，关键词覆盖单位、职位、专业、代码和备注；完整结果可导出 CSV。
- 岗位详情用右侧抽屉呈现：结论层、条件层、证据层、相邻周期对照层；缺失字段显示“未取得/无法唯一关联”等原因。
- 三年对照页加载 `changes.json`，显示新增、撤回、字段变更、待复核和“可比性”标签；不把分母不同的数字拼成趋势。
- 收藏只保存稳定 ID，筛选快照只保存条件和版本；CSV 使用 UTF-8 BOM 并防公式注入。
- 数据审计页将“公开边界”与“成绩待复核”分开，支持全部、高风险、未发布、连接歧义和待复核筛选。
- 岗位地图恢复为独立视图：岗位数/招录人数切换、真实十六市 GeoJSON 路径点击、城市检查器、`省直`独立口径、2024 区县/市直/宿松/广德归属提示，以及回到岗位检索的地图城市组筛选。
- 所有主要动作支持键盘焦点、Escape 关闭详情、关闭后焦点返回、`aria-live` 状态反馈和 reduced-motion。

## 5. 更新流程

1. 把新公告或源快照存入对应周期目录，登记 SHA-256、来源类型、发布方、定位和观察日期。
2. 更新周期 `cycle.json` / bundle，运行成绩构建、资格核查和三年审计。
3. 运行 `build_maintainable_site.py`，由同一 bundle 生成七类周期模块、两个全局审计模块和一个共享地图模块；地图仅从项目内真实 GeoJSON 投影，不与岗位计数绑定存储。
4. 运行磁盘校验：manifest 路径、文件字节数、SHA-256、岗位行数、招录合计、稳定 ID、成绩边界、三年汇总和十六市地图几何。
5. 运行 Python 单测、Node 单测、HTTP 浏览器烟测；检查 390、768、1440 宽度和 file:// 回退行为。
6. 通过后在 `deliverables/releases/<version>/` 保存发布快照和 manifest，再复制 ZIP 到桌面。

## 6. 单模块回滚

回滚前先选择同一周期、同一模块的上一版文件和 SHA-256，不能用其他周期文件替代。执行“目标路径在 release 目录内”检查后，以备份文件恢复，重新生成 `site-manifest.json` 并运行 `verify_maintainable_site.py`。若审计或哈希不通过，不标记为已发布。

当前工作区没有 Git 仓库，回滚依据是发布目录、ZIP、manifest 和 SHA-256，不以 commit 作为证据。

## 7. 当前真实边界

当前三年已对账为 28,678 岗、42,058 人；公开审计边界 8 项；成绩无法唯一匹配 116 条。边界在 `review-queue.json` 与周期 `audit.json` 中继续公开。不能把当前交接包内部可复现误写成所有外部官方逐岗资料都已取得。
