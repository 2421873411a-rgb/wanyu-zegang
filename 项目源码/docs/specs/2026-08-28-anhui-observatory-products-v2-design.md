# 皖域择岗档案 v2：双数据产品多页面重构设计规格

## 1. 目标

把当前两个“长报告式 HTML”升级为两个相互联动的离线数据产品：

- 岗位产品：负责发现城市机会、比较城市、检索具体岗位、回溯源表。
- 待遇产品：负责切换身份与工龄、比较城市待遇、阅读估算口径与城市档案。

页面必须保持可双击打开、无需服务器、无需联网；所有源文档事实和中性措辞保留，新增图形只使用可追溯的源数据或项目内真实安徽市级边界。

## 2. 设计原则

### 2.1 产品优先于海报

首页只承担一个任务：帮助用户快速形成判断并进入下一步。标题、装饰性渐变和大面积概念图退到背景，筛选器、数字、地图和表格成为主角。

### 2.2 证据优先

任何数字旁边都能说明它来自哪种口径：源表记录、聚合统计或报告估算。页面不生成岗位推荐、录取概率、竞争等级、城市综合评分，也不把待遇估算写成政策工资。

### 2.3 一套状态驱动所有视图

地图、城市检查器、排名、对比卡片、检索结果和 URL 读取同一份状态，而不是每个组件独立维护“当前指标”。

## 3. 页面信息架构

交付包生成 7 个正式页面，同时保留现有两个中文文件名作为兼容入口，入口指向新的岗位观测台和待遇观测台。

### 岗位产品

| 文件 | 页面职责 | 内容边界 |
|---|---|---|
| `岗位观测台.html` | 地图与机会概览 | 指标、筛选、16 市地图、检查器、摘要，不加载长源表 |
| `岗位排名对比.html` | 动态排名与城市比较 | 16 市排行、三/四城比较、考试类别构成、差值矩阵 |
| `岗位检索.html` | 具体岗位发现 | 多条件筛选、结果表、选入比较、CSV 导出 |
| `岗位档案.html` | 源文档追溯 | 106 张原始表、城市章节、字段说明、使用边界 |

### 待遇产品

| 文件 | 页面职责 | 内容边界 |
|---|---|---|
| `待遇观测台.html` | 身份与工龄地图 | 公务员/事业编、五阶段、地图、检查器、城市导航 |
| `待遇排名.html` | 城市待遇比较 | 五节点轨迹、身份切换、城市差值、排序 |
| `待遇档案.html` | 规则与城市档案 | 估算口径、31 张源表、16 市档案 |

### 共用外壳

所有页面共用：

- 64px 左右的紧凑产品导航栏。
- 当前产品、当前城市、数据更新时间和跨产品入口。
- 统一的 12 栏桌面栅格、8 栏平板栅格、4 栏手机栅格。
- 统一的按钮、标签、筛选器、表格、抽屉、空状态和无障碍焦点样式。

## 4. URL 与页面状态

### 4.1 岗位状态

```text
metric=jobs|recruits|ratio
city=合肥
exam=省考|事业单位|国考
q=信息化
compare=合肥-104-001,安庆-087-003
```

示例：

```text
岗位观测台.html?city=合肥&metric=recruits
岗位检索.html?city=合肥&exam=省考&q=信息化
岗位排名对比.html?metric=ratio&compare=合肥-004-001,滁州-013-002
```

### 4.2 待遇状态

```text
city=合肥
type=公务员|事业编
stage=刚入职|1年|3年|5年|10年
```

示例：

```text
待遇观测台.html?city=合肥&type=事业编&stage=10年
```

### 4.3 深链规则

- 从待遇城市档案进入岗位页时，保留 `city` 参数并定位到岗位检索。
- 从岗位页进入待遇页时，保留 `city` 参数并定位到待遇检查器。
- 未识别参数回退到默认状态：岗位数、全省、公务员、入职 3 年。
- 用户切换状态后使用 `history.replaceState` 更新 URL，不刷新页面。

## 5. 岗位地图工作台

### 5.1 状态模型

```js
{
  metric: 'jobs',
  city: null,
  exam: null,
  query: '',
  comparedJobs: []
}
```

### 5.2 指标联动要求

`renderJobView(state)` 必须同时更新：

1. 真实安徽 16 市边界的填色和选中描边。
2. 地图城市标签和悬停提示的数值及单位。
3. 图例的最低值、最高值和单位。
4. 右侧城市检查器的主数字、单岗平均和全省排名。
5. 考试类别构成图的岗位数及占比。
6. 动态排名的排序字段、数值列和占比条。
7. 三城/四城对比图和矩阵表。
8. URL 中的 `metric` 与 `city` 参数。

指标语义：

- `jobs`：岗位数，单位为“岗”。
- `recruits`：招录人数，单位为“人”。
- `ratio`：招录人数 ÷ 岗位数，单位为“人/岗”；岗位数为零时显示 `—`，不参与排序。

### 5.3 地图表现

- 地图路径来自 `anhui_340000_full.json`，不绘制近似轮廓。
- 颜色使用连续蓝色热力；选中状态使用双层蓝色描边和柔和光圈。
- 悬停卡显示城市、当前指标、岗位数、招录人数、单岗平均三项数据。
- 点击地图城市不强制跳走；检查器先更新，用户点击“查看完整岗位”才进入检索页。
- 地图底部城市胶囊只承担快速定位，不重复塞入大段文案。

## 6. 岗位排名与对比

### 6.1 动态排名

- 默认按当前地图指标降序排列。
- 缺失值置底，不把缺失当作 0。
- 每行显示：排名、城市、岗位数、招录人数、单岗平均、当前指标占比。
- 城市行可回到观测台并锁定该城市。

### 6.2 城市比较

- 默认显示 3 城，最多选择 4 城。
- 选择城市后重新渲染卡片、构成条、柱状图和数字矩阵。
- 支持岗位数、招录人数、单岗平均三种比较指标。
- 不输出“更好”“更适合”等结论，只做事实差异。

## 7. 岗位检索与比较工作台

### 7.1 检索

- 输入框支持单位、职位、职位代码和城市关键词。
- 城市、考试类别使用筛选器；筛选条件显示为可移除标签。
- 结果表保留源表字段，长内容在单元格内部处理，不造成页面级横向溢出。
- 输入 `/` 聚焦检索框；按 `Esc` 清除当前输入但不清空其他筛选。

### 7.2 比较抽屉

- 右侧抽屉替代占空间较大的固定底栏。
- 最多选 4 条岗位；每条岗位有稳定 `record_id`。
- 支持“只看不同字段”、复制摘要、导出 CSV、移除单条、清空全部。
- 选择保存在 `localStorage`；用户主动清空前保持。
- 缺失字段显示 `—` 或“该来源无此字段”，不推断、不补全。

## 8. 待遇产品

### 8.1 待遇观测台

- 身份类别和工龄阶段是同级控制器。
- 地图、检查器、热力图例、城市排名和轨迹节点跟随同一状态。
- 检查器显示估算金额、当前阶段、全省排序和相对省均值。
- 明确提示“统一口径估算，不代表政策规定工资或个人收入承诺”。

### 8.2 待遇排名与档案

- 排名页展示五个源数据节点，不在节点之间制造预测线。
- 档案页承载原始 31 张表、估算规则和城市层级说明。
- 每个城市档案提供“查看该城市岗位”和“返回待遇观测台”两个入口。

## 9. 视觉系统

### 9.1 方向

采用“白纸 + 蓝图 + 证据线”的研究型数据产品风格：

- 背景：雾白和浅蓝，不使用大面积深色渐变。
- 文字：深靛色主标题，蓝灰色说明，等宽数字。
- 主操作：电光蓝。
- 数据类别：青色表示事业单位，琥珀色表示国考，蓝色表示省考。
- 红色只用于警示或清空，不用于制造竞争紧张感。

### 9.2 版式

- 页面顶部不再使用超大海报式标题。
- 首屏最多一个主地图和一个检查器。
- 卡片圆角控制在 10–16px；关键区块使用细线、分栏和留白区分。
- 首页内容目标：桌面首屏可看到地图主结构；手机首屏进入控制器和地图，不加载源档案。

## 10. 动效规格

| 场景 | 动效 | 时长 |
|---|---|---:|
| 页面进入 | 导航、控制器、地图边界、检查器分层出现 | 180–650ms |
| 指标切换 | 地图颜色过渡、标签替换、数字滚动 | 260–420ms |
| 城市选择 | 区域描边、镜头光圈、检查器替换 | 180–260ms |
| 排名重排 | FLIP 位移与数值替换 | 320–360ms |
| 对比抽屉 | 滑入、岗位胶囊出现、移除反向收缩 | 180–240ms |

所有动画在 `prefers-reduced-motion: reduce` 下直接呈现最终状态；不使用自动轮播、不使用会阻塞阅读的连续动画。

## 11. 数据与构建架构

构建流程：

```text
Word → DocumentModel → JobDataset / SalaryDataset → 页面专属 HTML
```

- 岗位观测台只内联城市聚合数据和地图边界。
- 岗位检索页内联 544 条岗位记录。
- 岗位档案页内联 106 张原始表。
- 待遇观测台和排名页只内联待遇序列。
- 待遇档案页内联 31 张原始表。
- 每个页面仍然是可双击打开的单文件 HTML，不依赖外部 CDN。

## 12. 可访问性与兼容性

- 地图城市区域支持鼠标、键盘 Enter/Space 和可见焦点。
- 指标、身份、工龄按钮使用 `aria-pressed`。
- 检查器和筛选结果使用 `aria-live="polite"`。
- 表格保留表头、标题和源表编号。
- 390px、768px、1440px 三个视口无页面级水平溢出。
- 关闭 JavaScript 后，档案页面仍完整显示所有源文档文字和表格。

## 13. 验收标准

### 功能

- 地图切换三指标后，区域颜色、标签、图例、检查器、排名和对比图全部同步。
- 城市深链打开时，地图和检查器进入指定城市。
- 岗位比较最多 4 条，差异模式、复制和 CSV 导出有效。
- 待遇身份/工龄深链有效，城市档案可跳岗位检索。

### 数据

- 岗位记录仍为 544 条、招录合计 825 人，考试类别构成与源文档一致。
- 岗位档案保留 106 张表；待遇档案保留 31 张表。
- 所有源段落和非空单元格仍出现在对应档案页。
- 无新增推荐、概率或未经源数据支持的趋势结论。

### 质量

- Python 单元测试全绿。
- Playwright 在桌面和移动视口无控制台错误、无页面级水平溢出。
- 设计 QA 对照 5 张用户参考图，检查地图、间距、色彩、字体、动效和响应式状态。
- 交接包包含页面清单、计划、参考图、QA 报告、源文件和重建脚本。

## 14. 非目标

- 不接入在线职位 API。
- 不添加登录、云端同步或服务端数据库。
- 不根据岗位和待遇数据计算综合推荐分。
- 不覆盖用户提供的旧压缩包。
