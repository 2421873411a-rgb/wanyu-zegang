## 二、问题与机会清单（分级）

### P1 体验与性能（有实测证据）

1. **榜单/检索首开慢**：两视图需整载 `jobs.json`（2026 约 11MB、2025 约 13MB），本机实测首开 2–4 秒，弱网更差。已有 `palette.json`（1.4–1.6MB 轻索引）先例可复制。
2. **加载无感知**：视图切换后旧内容停留、无骨架/进度提示，用户在大 JSON 加载期间以为页面卡死。
3. **窄视口导航收纳缺失**：570px 下"使用说明/更新日志"需横向滚动导航条才能到达。
4. **v15.0.1 未入 CHANGELOG**：地图全省修复只有提交记录（045bac0），交付日志缺一条。

### P2 技术债与定位

1. **旧测试债**：`test_anhui_web.py` 8 个过期契约 + 写盘副作用，是唯一未清的发布链盲区。
2. **单文件定位含糊**：离线快照 `皖域择岗总览.html` 数据基线 v14.4、视觉层 v14，与维护站 v15 双主题不一致；用户从两个入口会看到两套观感。
3. **F10 PWA 延后未做**：外置 JSON 站在弱网/二次访问没有缓存策略。
4. **可访问性未做专项**：键盘/焦点/reduced-motion 已覆盖，但缺地标结构、读屏路径与全部芯片状态（含 `is-above-mean`、`is-diff`）的对比度全量校验。
5. **文档年代层**：早期 v12 命令段与现行发布流程并存于同一份文档（v15 交接已部分覆盖，缺一次统一梳理）。

### P0 正确性

本次审查未发现数据、聚合或语义正确性缺陷。

## 三、v15.1 计划：清债与打磨（单里程碑，可小步提交）

### M-A 检索/榜单加载体验（对应 P1-1/2）

- 新增每周期 `jobs_lite.json`（schema `wanyu-maintainable-jobs-lite/v1`）：仅检索/榜单所需列（id、代码、单位[:60]、职位[:60]、城市、考试、招录、分数观测、竞争观测、标签），预估 1.5–2.5MB/周期；`jobs.json` 降级为详情抽屉按需加载。
- 视图切换增加骨架占位与"正在加载 周期数据…"提示；加载失败保留旧内容并给重试按钮。
- 验收：检索/榜单首开可交互 < 1s（本机）；磁盘校验 185 + 新增 lite 交叉核对（行数==jobs 行数、ID 集合相等）。

### M-B test_anhui_web 清债（对应 P2-1）

- 8 个用例断言对齐 v15 结构或删除；**移除向 `deliverables/` 写盘的副作用**（改为临时目录输出）。
- 完成后把该模块纳入 `release.py` 门禁链；根/deliverables 两份 HANDOFF 撤销"隔离工作区"警告。
- 验收：发布链 20 模块全绿（120→128+ 用例）。

### M-C 导航窄屏收纳（对应 P1-3）

- 溢出项收纳进"更多"菜单或允许导航换行（二选一，以走查截图定稿）。
- 验收：570/390px 无导航横向滚动可达全部视图。

### M-D 日志补记（对应 P1-4）

- CHANGELOG 增补 v15.0.1 地图条目；HANDOFF 同步一句。

### M-E 可访问性专项（对应 P2-4）

- 补 `main/skip-link/aria-live`（加载与筛选结果变化播报）；芯片/徽标全部状态对比度进 `test_ui_v15` 数学回归。
- 验收：新增对比度用例全绿；内置浏览器键盘走查（Tab 顺序 + Enter/Space/Esc）通过。

## 四、v16 计划：能力升级（三里程碑）

### v16-M1 性能与离线（依赖 v15.1 M-A）

- **F10 PWA**：service worker + manifest，外置 JSON 按 manifest SHA-256 分版本缓存；离线时读缓存并在页头标注"离线缓存 · 构建版本"。验收：断网二次打开全视图可用。
- **周期数据分片**（可选增强）：jobs.json 按城市组分片，检索按需取片；需同步磁盘校验与 DataStore 重试逻辑。

### v16-M2 数据工作台

- **更新向导**：把《数据更新操作手册》变成页面内 checklist（登记来源 → 替换模块 → 重建 → 磁盘校验 → 回归），一键调 `verify_maintainable_site.py` 并回显 185 项结果；不替代命令行，只降低门槛。
- **收藏/快照导入导出**：本地数据一键导出 JSON、跨机器导入（带版本与容量校验）。
- **变更摘要**：本地基于 changes.json 生成"本期新增/撤回/待复核"订阅式摘要页。

### v16-M3 单文件定位决策（D5，二选一）

- **方案 A（推荐）**：明确单文件为"数据归档快照"定位——顶部加提示条"最新交互与双主题见维护站入口"，视觉冻结 v14，不再同步；工程量≈0，语义清晰。
- **方案 B**：把 Token v3 视觉层移植进单文件构建链；工程量大，且需重验 51 项反解析门禁与 <80MiB。

### 门禁扩展原则（沿用 v15 先例）

- 任何新数据模块 → MODULE_SCHEMAS + 数学交叉核对（行数/合计/ID 可对回源）。
- 每里程碑收口：磁盘校验 + 全链单测 + 内置浏览器走查（控制台 0）+ 新增契约测试。
- 性能验收进常驻：检索/榜单首开 <1s（本机）作为回归断言基线记录。

## 五、顺序与依赖

1. v15.1 五项可并行；**M-A 先行**（用户感知最大），M-B 紧随（决定 test_anhui_web 何时进门禁）。
2. v16-M1 依赖 M-A 的 lite 索引；v16-M3 决策不阻塞其余项，可随时拍板。
3. 红线不变：岗位原文不改、未知不以 0 代替、离线无远程资源、单文件 <80MiB。
4. 每步沿用"边做边审核"：实现 → 门禁 → 内置浏览器走查 → 提交。
