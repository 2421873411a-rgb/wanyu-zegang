# 皖域择岗总览 v6 迭代计划与执行记录

## 目标

把岗位机会页和待遇分析页合并成一个更综合的离线决策入口，让用户按“先定口径 → 选城市 → 看机会与待遇 → 保留短名单 → 下钻原表”的顺序完成判断。岗位页和待遇页继续保留为兼容入口，避免旧链接失效。

## 设计方向

采用“浅色数据编辑室”而不是深色大屏：纸白卡面、雾蓝背景、深靛标题、钴蓝主操作、青色机会层、琥珀待遇层和少量珊瑚警示。借鉴现代 AI 产品的克制导航、明显主任务和渐进披露，但不复制品牌视觉，也不使用无意义的炫光、玻璃拟态或装饰性大图。

## 产品结构

| 层级 | v6 入口 | 作用 |
| --- | --- | --- |
| 00 | 全省总览 | 统一考试类别、身份类型、工龄和城市状态 |
| 01 | 机会地图 | 进入岗位指标、地图、城市检查器和决策驾驶舱 |
| 02 | 待遇地图 | 进入身份 / 工龄热力图与待遇检查器 |
| 03 | 我的短名单 | 保存值得继续比较的城市，并继续进入岗位短名单 |
| 04 | 原始档案 | 在岗位 106 张表和待遇 31 张表之间切换 |

## 核心交互逻辑

1. 总览默认 `全部类别 · 公务员 · 3年 · 合肥`。
2. 考试类别切换后，岗位 KPI、矩阵横轴和城市画像岗位 / 招录数字同步重算。
3. 身份类型和工龄切换后，待遇 KPI、矩阵纵轴和待遇画像同步重算。
4. 点选矩阵城市后，城市画像和 URL `city` 同步更新；用户可以进入岗位地图或待遇地图。
5. 加入短名单后写入版本化本地存储键；短名单页同时保留城市清单和岗位收藏 / 对比工作流。
6. 原始档案页用页签选择岗位源档案或待遇源档案，目录搜索、折叠和全文内容保持原逻辑。

## 数据与安全边界

- 岗位数量、招录人数和考试类别构成来自岗位源表；待遇数值来自待遇报告的估算序列。
- “综合位置”只表达当前两组城市聚合值的相对位置，不是录用预测、城市推荐或收入承诺。
- 不新增在线接口、登录、数据库、远程字体、远程脚本或外部地图服务。
- 所有源段落和表格仍在对应档案视图中保留；总览只携带必要的紧凑数据。
