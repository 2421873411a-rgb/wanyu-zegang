# 皖域择岗长期维护网站架构方案 v1

更新日期：2026-09-01  
适用范围：2024、2025、2026 三个数据周期

## 1. 交付形态

当前交付采用“双轨”结构：

| 入口 | 用途 | 数据方式 | 适合场景 |
| --- | --- | --- | --- |
| `deliverables/皖域择岗总览.html` | 完整离线快照 | 三周期载荷内嵌，打开即用 | 没有服务器、需要归档或发送单文件 |
| `deliverables/maintainable/index.html` | 长期维护站 | HTML 壳 + 按周期/模块外置 JSON | 持续更新、静态托管、多人维护 |

两者都由同一条数据链生成，不允许在页面里手工改岗位数字。单文件是稳定回退入口，维护站是以后迭代的主入口；二者不互相替代。

## 2. 数据分层

```text
source_docs / source_data
        ↓
现有解析器与标准化字段
        ↓
tools/anhui_web/unified_cycle_bundle.py
        ↓
三年冻结基线 + three_year_audit.json
        ↓
build_maintainable_site.py
        ├─ data/site-manifest.json
        ├─ data/audit/three-year.json
        └─ data/cycles/{2024,2025,2026}/{overview,jobs,audit}.json
        ↓
maintainable-site.js 按周期懒加载
```

`overview.json` 只保留周期摘要，`jobs.json` 保留 `allMajors.rows` 和必要元数据，`audit.json` 保留当前周期证据边界；三年审计索引单独位于 `data/audit/three-year.json`。应用层只负责筛选、聚合和呈现，不重写源字段。manifest 为每份模块记录岗位数、招录人数、边界数量、未唯一匹配数量、字节数和 SHA-256，便于只替换一个模块后对账。

## 3. 当前功能边界

维护站提供五个长期稳定的核心入口：

1. 周期总览：加载当前周期的岗位、招录、成绩安全关联和未唯一匹配计数，并展示城市分布。
2. 三年对照：不先加载三份完整岗位行，仅使用 manifest 摘要比较 2024—2026；点进具体周期后再加载对应 JSON。
3. 岗位榜单：按城市聚合当前周期岗位行；支持岗位数/招录人数排序和专业输入/候选选择。专业过滤匹配岗位表原始 `zy` 文本，筛选后重新聚合城市，不篡改源行。
4. 岗位检索：对单位、职位、专业、代码和备注做关键词检索，并支持城市、考试类别筛选；首屏展示最多 120 行，完整数据仍在 JSON 中。
5. 数据审计：显示三年审计汇总、周期证据层、审计快照、公开缺口、成绩无法唯一匹配数量、源链路和处理规则。

当前仍然遵守这些事实边界：

- 2024：10,017 岗、15,331 人；2025：10,150 岗、14,721 人；2026：8,511 岗、12,006 人。
- 2026 成绩附件存在 116 个无法唯一匹配项，继续安全留空。
- 未发布、未回收或只有汇总口径的资料保持公开缺口，不填成 0，也不生成“全部官方数据已补齐”的结论。
- 待遇模块仍是 2026 快照口径，不在 2024/2025 页面冒充历史待遇。

## 3.1 专业候选的展示层数据契约

专业字段分为“源事实”和“候选展示”两层：

- `allMajors.rows[*].zy` 是源岗位专业原文，必须完整保留，供岗位详情、关键词检索和审计复核使用。
- 画像、岗位地图、岗位榜单和维护站候选只展示可读值：清理前置数字/符号编码残片，过滤纯数字/纯符号值，去重并排序。
- 展示层清洗不能把未知专业改成“专业不限”，也不能把缺失值推断为任何专业；用户手工输入仍按原始 `zy` 文本匹配。
- 新周期接入时，先在 bundle 生成后检查源字段，再由 `product-all.js`、`product-jobs-ranking.js` 和 `maintainable-site.js` 各自的展示适配层生成候选，不在 JSON 内破坏源字段。

这套契约解决“候选框出现纯数字”的可用性问题，同时避免为了美化 UI 而篡改数据事实。

## 3.2 浅色工作台视觉原则

维护站与单文件视觉层采用浅色 AI 工作台方向：白色内容面、浅灰上下文层、细边框、低强度阴影、较大留白和单一蓝色关键态。参考现代 AI 产品的层级、输入反馈和响应式布局，不复制具体品牌颜色、图标或素材。数据状态继续使用青色/琥珀色等语义标记，缺口与不可比不得被视觉成功态覆盖。

## 4. 更新流程

### 4.1 修改源数据或解析器后

在项目根目录执行：

```powershell
python tools/anhui_web/build_score_lists.py --cycle 2026
python tools/anhui_web/build_score_lists.py --cycle 2025
python tools/anhui_web/build_score_lists.py --cycle 2024
python tools/anhui_web/audit_three_years.py --root . --output-json tools/anhui_web/data/three_year_audit.json --report docs/三年数据真实性与完整性审计_v12.md
python tools/anhui_web/build_pages.py --output-dir deliverables
python tools/anhui_web/build_maintainable_site.py --root . --output-dir deliverables/maintainable
```

日期字段优先来自源快照/审计日期。构建当天日期不能被写入周期载荷，否则会造成没有数据变化却出现哈希漂移。

### 4.2 本地查看维护站

不能直接双击 `index.html` 依赖 `file://` 读取 JSON；浏览器会按安全策略阻止 `fetch`。使用：

```powershell
python tools/anhui_web/serve_maintainable.py --port 8765
```

然后访问 `http://127.0.0.1:8765/index.html`。部署到任意静态 HTTP 托管时，将整个 `deliverables/maintainable/` 目录作为站点根目录即可。

## 5. 发布门禁

发布必须经过以下顺序：

1. Python 单元测试：解析、数据质量、三年审计、单文件循环、UI 契约、维护站契约。
2. `verify_single_file_v12.py prebuild`：源数据字节数和 SHA-256 对照冻结基线。
3. 三年审计：内部检查无失败，公开边界仍登记。
4. 页面构建和 `postbuild`：单文件载荷可解析，三周期数量与审计信封存在。
5. Node 核心测试和单文件 Playwright 烟测：周期切换、检索、收藏、对比、响应式和无远程资源。
6. 维护站 HTTP Playwright 烟测：manifest 加载、2024/2025/2026 切换、岗位榜单专业筛选、检索、边界页、390/768/1440 宽度和本地 JSON 请求。
7. 维护站磁盘校验：重新读取 `data/site-manifest.json`、三类周期模块和 `data/audit/three-year.json`，核对哈希、岗位行、招录合计、稳定 ID 与三年汇总。
8. 生成 ZIP 后再次执行 package verifier，检查最终压缩包中的单文件交付入口。

任一门禁失败都不应发布。尤其不能因为页面能打开，就跳过数据基线、审计或来源状态检查。

## 6. 回滚与扩展

### 回滚

维护站的可回滚单元是 `data/cycles/{year}/{module}.json` 和对应 manifest。发现某周期岗位、摘要或审计数据异常时，只恢复对应模块上一份已验收 JSON，重新生成 manifest 并重跑门禁；单文件快照仍可独立使用，不受在线维护站影响。

### 下一阶段扩展

现阶段使用静态 JSON 是成本最低、最容易审计和部署的长期方案，不需要立即引入数据库。当前已完成第一阶段的周期/模块拆分；数据量和访问量显著增长后，再按以下顺序扩展：

- 将岗位模块进一步拆为 `positions`、`scores`、`catalog` 多个文件，按视图继续懒加载。
- 为岗位行增加稳定版本号和变更日志，支持“本次新增/修订/撤回”视图。
- 需要多人编辑或服务端查询时，再把已审计 JSON 导入数据库/API；数据库仍以审计后的 JSON 为导入源，不允许绕过审计直接写前端。
- 引入静态托管缓存时，manifest 的哈希作为缓存失效依据，避免浏览器拿到旧周期文件。

## 7. 维护责任边界

- 数据事实：由源文件、解析器、周期 bundle 和审计报告共同负责。
- 页面表现：由 `templates/maintainable-site.js` 与 `.css` 负责。
- 交付一致性：由 `release.py` 负责一次性生成单文件、维护站和 ZIP。
- 真实性表达：任何“已核验”“源包”“未发布”“无法唯一匹配”标签必须来自审计状态，不能由 UI 文案自由推断。
