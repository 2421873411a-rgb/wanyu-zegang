# 皖域择岗档案｜制作与维护说明

## 1. 正式成品

- `皖域择岗总览.html`：单文件离线入口，内含 2024、2025、2026 三个周期，可直接双击打开。
- `maintainable/index.html`：长期维护入口，HTML 只放应用壳；数据位于 `maintainable/data/cycles/<cycle>/{overview.json,jobs.json,audit.json}` 和 `maintainable/data/audit/three-year.json`，通过本地 HTTP 按视图加载。
- `HANDOFF.md`：最终交接说明；数据边界、验收证据和两个入口以该文件为准。
- `legacy_v11/`：旧版分拆页面归档，仅用于追溯，不是正式入口。

单文件适合归档、转发和无服务器使用；长期维护站适合以后替换单个周期模块、部署静态站点和继续迭代 UI。两种入口使用同一条 bundle / 审计链，不允许在 HTML 内手工改岗位数字。

## 2. 使用方式

1. 双击 `皖域择岗总览.html`，顶部切换 2024 / 2025 / 2026。
2. 进入“岗位榜单”后，可先输入或选择专业，再按岗位数、招录人数或竞争比排序；“清空专业”恢复全量城市。
3. “全岗位库”的“我的专业”和“岗位地图”也支持可读候选；候选框过滤纯数字/纯符号编码，原始岗位专业仍可在详情和原始档案中复核。
4. 岗位检索支持关键词、城市、考试类别、资格标签、分页、岗位详情、收藏、对比和 CSV 导出；收藏、备注和对比按周期隔离。
5. 长期维护站必须通过 HTTP 访问，不能双击后依赖 `file://` 读取 JSON：

```powershell
python tools/anhui_web/serve_maintainable.py --port 8765
```

打开 `http://127.0.0.1:8765/index.html`。

## 3. 数据规模与真实性边界

| 周期 | 全量岗位 | 招录人数 |
| ---: | ---: | ---: |
| 2024 | 10,017 | 15,331 |
| 2025 | 10,150 | 14,721 |
| 2026 | 8,511 | 12,006 |

上述是当前交接包内部可复现、可对账的聚合口径，不等于所有外部官方逐岗资料均已发布或取得。当前审计报告登记的公开资料边界共 8 项；未发布、未回收、只有汇总口径或无法唯一匹配的值保持空值，不填成 0。

- 2026 成绩附件有 116 个无法唯一匹配项，继续安全留空。
- 2026 事业编成绩收割仍受公告发布边界约束。
- 2024 / 2025 的省考逐岗合格/缴费、部分拟聘用和事业编明细按周期报告中的状态展示。
- 待遇模块是 2026 快照口径，不冒充 2024 / 2025 历史待遇。

详细边界见 `../docs/三年数据真实性与完整性审计_v12.md`、页面“三年对照”和维护站“数据审计”。

## 4. v13.3 UI 与专业候选升级

- “我的专业”、岗位地图、岗位榜单和维护站使用统一的展示层清洗：去除前置数字/符号残片，过滤纯数字/纯符号值，去重排序。
- `allMajors.rows[*].zy` 原始字段、岗位代码、资格条件和证据链不改；清洗只作用于候选控件展示。
- 单文件构建器每个周期重新生成岗位地图与全岗位库视图，避免旧 HTML 骨架把旧候选带回三年入口。
- 顶部采用白底、浅灰上下文带、细边框、低强度阴影和蓝色关键态，借鉴现代 AI 工作台的留白、层级和输入反馈，不复制 DeepSeek 品牌资源。
- 关键交互保持本地可复核：周期切换、专业筛选、排名重算、清空恢复、检索、边界查看和响应式布局均有自动化验收。

## 5. v13.4 审计中心、数据分层与组合筛选

- `overview.json` 只保留当前周期总览摘要，`jobs.json` 只承载全量岗位行，`audit.json` 只承载当前周期的证据边界和成绩待复核量。
- `data/audit/three-year.json` 是三年审计索引，汇总 2024、2025、2026 的岗位、招录、缺口、证据层和无法唯一匹配成绩。
- 维护站“数据审计”视图显示三年对照和当前周期缺口；“岗位榜单”支持专业、城市、考试、岗位类型组合筛选。
- 更新单个周期时只替换对应模块并重新生成 `site-manifest.json`；manifest 会记录每个模块的字节数和 SHA-256。

## 6. 更新流程

修改源资料或解析器后，在项目根目录执行：

```powershell
python tools/anhui_web/build_score_lists.py --cycle 2026
python tools/anhui_web/build_score_lists.py --cycle 2025
python tools/anhui_web/build_score_lists.py --cycle 2024
python tools/anhui_web/audit_three_years.py --root . --output-json tools/anhui_web/data/three_year_audit.json --report docs/三年数据真实性与完整性审计_v12.md
python tools/anhui_web/build_pages.py --output-dir deliverables
python tools/anhui_web/build_maintainable_site.py --root . --output-dir deliverables/maintainable
```

正式发布使用：

```powershell
python tools/anhui_web/release.py --zip
```

发布链会执行源审计、单元测试、单文件前后构建校验、Node 测试、单文件浏览器 smoke、维护站磁盘模块校验、维护站 HTTP smoke 和 ZIP 校验。

## 7. 数据与页面责任边界

- 源文件、解析器、周期 bundle 和审计报告负责事实、来源、状态与缺口。
- `templates/product-all.js`、`product-jobs-ranking.js` 和 `maintainable-site.js` 负责专业候选展示和交互，不负责改写事实。
- `templates/ui-v13.css` 与 `templates/maintainable-site.css` 负责视觉呈现，不改变统计口径。
- 任何“已核验”“源包”“未发布”“无法唯一匹配”标签必须来自审计状态，不能由页面自由推断。
